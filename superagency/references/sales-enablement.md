# Sales Enablement

Covers: one-pagers, objection-handling docs, demo scripts, pitch decks, rep email templates, competitive talk tracks.

Often pairs with: `competitive.md` (battlecards feed the objection doc), `positioning.md` (the deck is positioning made concrete), `persona.md` (who the rep is talking to).

## Before writing
Ask who uses it and when in the cycle — a cold-outreach template and a late-stage security-objection doc share nothing. Ask what's actually losing deals, and build for that rather than for completeness.

## One-pager / leave-behind
One page. The buyer's problem → what changes with the product → one proof point → one clear next step. Written for the buyer to forward internally, not for the rep to read aloud.

## Objection handling
Per objection: the objection in the buyer's words → what's usually behind it → the response → the proof. One line each. An objection doc nobody can scan mid-call doesn't get used.

Cover the ones the field actually hears — price, "we'll build it", incumbent lock-in, timing, "just send me information". Don't invent objections nobody has raised.

## Demo script
A path, not a feature tour. Open on the buyer's problem, show the two or three moments that resolve it, stop. Mark where reps usually lose the room.

## Pitch deck
Ten slides or fewer for the core narrative: problem → why now → the shift → the product → proof → the ask. The appendix carries detail. Every slide maps to a positioning pillar or it's cut.

## Output
One-pagers, objection docs, demo scripts, decks → file (the field reuses them). Individual email templates and talk-track lines → inline.

## Red flags
| Thought | Reality |
|---|---|
| "I'll cover every objection a buyer could raise." | An unscannable doc is a dead doc. Five real objections beat twenty hypothetical ones. |
| "The one-pager should list what the product does." | It should state the buyer's problem and what changes. A feature list doesn't get forwarded. |
| "I'll write proof points that sound convincing." | Proof is customer names, numbers, and outcomes the user gave you. Invented proof is a fabricated claim in a rep's hands. |
| "More slides means a more complete pitch." | Ten slides carry the narrative; the rest is appendix. A long deck buries the argument. |

## Rules
- Never invent proof points, customer names, or metrics for sales collateral — flag where the user must supply them.
- Build for the deals actually being lost, not for coverage. Ask what the field is hearing.
- Flag any competitive claim that needs substantiation before a rep can say it out loud.
